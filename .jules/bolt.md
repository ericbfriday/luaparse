## 2024-05-23 - luaparse string matching optimization
**Learning:** In hot parser/lexer loops, replacing `String.prototype.indexOf` lookups (e.g., `'xX'.indexOf(char) >= 0`) with direct `charCodeAt` or strict equality comparisons (e.g., `char === 'x' || char === 'X'`) is a significant micro-optimization in JavaScript. `charCodeAt` is particularly fast because it avoids allocating new string primitives for single characters. Out-of-bounds `charCodeAt` returns `NaN` which is safe for `===` comparisons.
**Action:** When working on lexers, parsers, or any character-by-character string processing loops in JavaScript, always prefer `charCodeAt()` or inline `===` logic over higher-level string functions like `indexOf()` or `includes()` to minimize allocations and maximize throughput.
