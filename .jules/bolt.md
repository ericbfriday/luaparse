## 2024-06-15 - Array.prototype.indexOf vs Object.create(null) for identifier tracking
**Learning:** Using `Object.create(null)` for tracking identifier scopes in performance-sensitive JavaScript code provides significant execution speedups compared to array-based lookups (`Array.prototype.indexOf`), but using `Object.assign` to copy these dictionaries when entering new block scopes is significantly slower than array `.slice()`. To maintain performance when entering new block scopes with dictionaries, use prototypical inheritance (`Object.create(parentScope)`) rather than shallow copying.
**Action:** Apply `Object.create(null)` for initial scopes and `Object.create(parentScope)` for new scopes to replace `Array.prototype.indexOf` and `Array.prototype.slice` in `luaparse.js` for identifier tracking. Ensure a safe fallback for environments missing `Object.create`.
## 2024-06-15 - Safe object dictionary fallback for identifier tracking
**Learning:** Using `{}` as a fallback for `Object.create(null)` can lead to prototype pollution and incorrect scope tracking if keys collide with `Object.prototype` properties (like `toString`). Furthermore, using `Object.assign` as a fallback for environments missing `Object.create` will crash ES3 environments.
**Action:** When creating dictionary-based lookups, use a prefix like `$` for keys to avoid prototype collisions when using `{}` as a fallback. Iterate with a `for...in` loop and `hasOwnProperty` instead of `Object.assign` to ensure ES3 compatibility for older environments.
