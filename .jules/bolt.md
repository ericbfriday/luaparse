## 2024-06-01 - Optimize indexOf with character codes
**Learning:** Checking for specific characters using `indexOf` on a string (like `',;'.indexOf(char) >= 0`) causes a measurable performance overhead due to string allocations and method call overheads. In the hot path of a lexer/parser, like in `luaparse.js`, this adds up to slow down execution.
**Action:** Replace `indexOf` checks for small character sets with strict equality checks using `===` or `charCodeAt` for single character matching over `String.prototype.indexOf`, as it significantly reduces execution time. Out-of-bounds `charCodeAt` safely returns `NaN` for `===` comparisons.
## 2024-06-25 - Optimize nested block scopes with dictionaries
**Learning:** For tracking scopes or identifier names in performance-sensitive JavaScript code, use dictionary-based lookups (`Object.create(null)`) instead of `Array.prototype.indexOf`, as it provides significant execution speedups. When optimizing nested block scopes, dictionary-based lookups are faster than array `indexOf` for tracking identifiers. To maintain performance when entering new block scopes with dictionaries, use prototypical inheritance (`Object.create(parentScope)`). Important: Do NOT use `Object.assign({}, parent)` as a fallback for older environments lacking `Object.create` (ES5), because `Object.assign` is an ES6 feature and will crash. Use the standard ES3 constructor fallback: `var F = function () {}; F.prototype = parentScope; return new F();`.
**Action:** Replace array `indexOf` with dictionary lookups for tracking scopes or identifier names in performance-sensitive JavaScript code.
